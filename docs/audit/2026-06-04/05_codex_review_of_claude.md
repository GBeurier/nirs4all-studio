## 1. Verdict & Calibration

Claude’s audit is broadly correct on the major risks: local API security, event-loop blocking, CI weakness, broken runtime endpoints, and Electron updater mismatch are real. It is also somewhat overstated in scope and precision: several counts/line references are stale, and some claims apply only to specific legacy/helper endpoints rather than whole modules. Severity is mostly reasonable for security and blocking work, but the roadmap under-prioritizes immediate API hardening.

## 5. Roadmap Critique

The roadmap is directionally right, but Phase 0 should not start with dead-code deletion. The first action should be **local API hardening**: restrict CORS to the actual renderer/dev origins, add a startup bearer token for mutating routes, and temporarily disable or gate `/updates/*`, dependency install/uninstall, dataset delete-with-files, and updater apply. That closes the active RCE/destructive surface before cleanup work.

After that, add CI gates that would catch the known breaks: `master` on main CI, blocking Vitest, pytest/import-smoke that imports all routers and resolves route helpers, plus Playwright Python/venv setup. Then fix dead runtime endpoints and the CPU packaging dependency gap. Performance offloading is important, but it should follow the security and “backend actually imports/runs” fixes.
