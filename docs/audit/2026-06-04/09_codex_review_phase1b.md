**Findings**

**High:** The shared `StoreAdapter` has a use-after-close race on workspace switch/unlink. `get_active_store_adapter()` returns the adapter/store under the manager lock, but requests then use the raw store later in `to_thread` without holding any lease: [api/aggregated_predictions.py](/home/delete/nirs4all/nirs4all-studio/api/aggregated_predictions.py:173), [api/aggregated_predictions.py](/home/delete/nirs4all/nirs4all-studio/api/aggregated_predictions.py:202). Meanwhile `activate_workspace()` / active unlink close the cached adapter immediately: [api/workspace_manager.py](/home/delete/nirs4all/nirs4all-studio/api/workspace_manager.py:2205), [api/workspace_manager.py](/home/delete/nirs4all/nirs4all-studio/api/workspace_manager.py:2718), [api/workspace_manager.py](/home/delete/nirs4all/nirs4all-studio/api/workspace_manager.py:2744). If that happens before a worker starts, or between multi-query calls like chain detail, `WorkspaceStore._ensure_open()` raises `RuntimeError("WorkspaceStore is closed")`: [workspace_store.py](/home/delete/nirs4all/nirs4all/nirs4all/pipeline/storage/workspace_store.py:288). The old per-request store did not have another request closing its connection.

**Medium:** Some modified `api/workspace.py` store-backed branches still do blocking SQLite/store work on the event loop and still churn per-request scanners/adapters. `get_workspace_runs()` calls `scanner._has_store()` and `scanner.discover_runs()` synchronously: [api/workspace.py](/home/delete/nirs4all/nirs4all-studio/api/workspace.py:1658), [api/workspace.py](/home/delete/nirs4all/nirs4all-studio/api/workspace.py:1663). `get_workspace_predictions_data()` synchronously calls `scanner.store_adapter.get_predictions_page(...)`: [api/workspace.py](/home/delete/nirs4all/nirs4all-studio/api/workspace.py:1989), [api/workspace.py](/home/delete/nirs4all/nirs4all-studio/api/workspace.py:1992). Those paths can open/use `WorkspaceStore` through `WorkspaceScanner.store_adapter`: [api/workspace_manager.py](/home/delete/nirs4all/nirs4all-studio/api/workspace_manager.py:154), [api/workspace_manager.py](/home/delete/nirs4all/nirs4all-studio/api/workspace_manager.py:162).

**Medium:** The new manager cache does not match `WorkspaceScanner`’s supported workspace layouts. `WorkspaceScanner` looks for stores under both `workspace_dir` and `workspace_path`: [api/workspace_manager.py](/home/delete/nirs4all/nirs4all-studio/api/workspace_manager.py:167). **Medium:** `_dataset_cache` is now mutated from worker threads but has no lock. **Verified**

`WorkspaceStore` does use `check_same_thread=False` and an internal `RLock`: [workspace_store.py](/home/delete/nirs4all/nirs4all/nirs4all/pipeline/storage/workspace_store.py:235), [workspace_store.py](/home/delete/nirs4all/nirs4all/nirs4all/pipeline/storage/workspace_store.py:250). The aggregated-prediction test fixture change matches the new ownership model and does not obviously weaken endpoint method/shape assertions, but it does not cover the invalidation/in-flight lifecycle race.
