## Summary

- Quality gates are the largest risk: CI currently lets Vitest fail, never runs pytest, and Playwright setup can proceed without a usable backend.
- Release/update paths have concrete breakages: the webapp download job passes the wrong type, legacy PyInstaller points at missing `launcher.py`, and the updater cannot handle the Electron artifacts it publishes.
- `npm run build` does run `validate:nodes && tsc -b`, but Electron release builds do not run `tsc`, and `electron/**/*.ts` is outside the TS project.
- The initial frontend bundle is likely too large: routes and heavy chart/3D modules are imported eagerly, with a current built `dist` snapshot showing a ~3.9 MB main JS chunk.
- Python dependency/build reproducibility is weak: lower-bound requirements, no pip lock, GPU requirements that do not install GPU deps, and release workflows that can continue after GPU install failure.
- Static/read-only audit only; `node`/`npm` were unavailable in this shell, so no fresh build, audit, or test run was executed.
