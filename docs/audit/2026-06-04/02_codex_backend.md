## Summary

- The main backend bottleneck is confirmed: I counted ~285 `async def` functions, only 2 `run_in_executor` uses, and ~99 blocking I/O / subprocess / model-load signatures. Several heavy pandas, sklearn, SHAP, parquet, zip, SQLite/store, and subprocess paths run directly in async handlers.
- Workspace/SQLite access is sync, repeatedly reopened, sometimes unclosed, and often performs full result scans for pages, summaries, and dashboards.
- `api_cleaning.md` is partly stale: `shared/filter_operators.py`, primary `predict_*` endpoints, synthesis components, and training have been partly refactored toward `nirs4all`. It still correctly flags major residues in SHAP, metrics, confidence/explain prediction paths, raw `.joblib`, and evaluation cross-validation.
- Security risk is high if this backend is reachable from a browser: wildcard CORS plus no visible auth exposes package install, venv, model deletion, workspace import/export, and update controls.
- Large god files are not just large; they mix routes, persistence, scanners, registries, migrations, execution orchestration, UI transforms, and ML helpers in ways that make performance fixes hard to land safely.
